# 2026-10-18 versiyasini serverga chiqarish

Ushbu yangilanish admin/sayt kontent sinxronlashini, intervyu nashr holatini, unvon filtrlarini, modal skrollini va responsiv menyularni tuzatadi. Yangi database migratsiyasi qo'shilmagan. Server bazasi, akkauntlar, yuklangan media va `.env` saqlanadi. Lokal SQLite, test sessiyasi va loglar GitHubga kiritilmaydi.

Quyidagi buyruqlar repodagi mavjud Docker Compose sozlamalariga mo'ljallangan: loyiha `/var/www/alumni`, SSH port `24050`, backend `127.0.0.1:8005`, frontend `127.0.0.1:3005`. Serverning o'zi ushbu ish davomida o'zgartirilmagan.

## 1. Ulanish va tekshirish

```bash
ssh -p 24050 root@213.230.96.104
cd /var/www/alumni
git status --short
docker compose ps
docker compose config --quiet
```

`git status` serverdagi o'zgartirilgan tracked fayllarni ko'rsatsa, ularni avval saqlab/ko'rib chiqing; `git reset --hard` bilan yo'qotmang. Mavjud Compose loyiha nomi va `.env`ni almashtirmang. `backend`, `frontend`, `db`, `redis` xizmatlari shu konfiguratsiyada mavjud bo'lishi kerak.

## 2. Qaytish uchun eski versiyani saqlash

Quyidagi bosqichlarni bitta SSH terminalida bajaring; `backup` o'zgaruvchisi keyingi buyruqlarda ishlatiladi.

```bash
umask 077
stamp=$(date +%Y%m%d-%H%M%S)
backup="$HOME/alumni-backups/$stamp"
mkdir -p "$backup"
git rev-parse HEAD > "$backup/previous-commit.txt"
cp .env docker-compose.yml "$backup/"
backend_id=$(docker compose ps -q backend)
frontend_id=$(docker compose ps -q frontend)
test -n "$backend_id" && test -n "$frontend_id"
docker image tag "$(docker inspect --format '{{.Image}}' "$backend_id")" "alumni-backend-rollback:$stamp"
docker image tag "$(docker inspect --format '{{.Image}}' "$frontend_id")" "alumni-frontend-rollback:$stamp"
printf 'services:\n  backend:\n    image: alumni-backend-rollback:%s\n  frontend:\n    image: alumni-frontend-rollback:%s\n' "$stamp" "$stamp" > "$backup/rollback-images.yml"
echo "Zaxira: $backup"
```

## 3. Kod va image'larni yangilash

```bash
git pull --ff-only origin main
git log -1 --oneline
docker compose build backend frontend
docker compose run --rm --no-deps backend python manage.py check
docker compose run --rm --no-deps backend python manage.py migrate --check
```

Har bir buyruq muvaffaqiyatli tugagandan keyingisiga o'ting. Build yoki tekshiruv xato bersa, mavjud ishlayotgan servislarni to'xtatmang. `migrate --check` qo'llanmagan migratsiya topsa, avval uning rejasini tekshiring (`python manage.py migrate --plan`); ushbu versiyada yangi migratsiya yo'q.

## 4. Baza/media zaxirasi va servislarni almashtirish

Bu bosqichda qisqa uzilish bo'ladi. PostgreSQL ishlatilayotganini tasdiqlang:

```bash
docker compose exec -T backend python manage.py shell -c 'from django.conf import settings; print(settings.DATABASES["default"]["ENGINE"])'
```

Natija `django.db.backends.postgresql` bo'lganda:

```bash
docker compose stop frontend backend
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > "$backup/database.sql"
test -s "$backup/database.sql"
mkdir -p "$backup/media"
docker cp "$backend_id:/app/media/." "$backup/media/"
docker compose run --rm --no-deps backend python manage.py collectstatic --noinput
docker compose run --rm --no-deps backend python manage.py shell -c 'from django.core.cache import cache; cache.clear()'
docker compose up -d --no-build backend frontend
```

Zaxira buyrug'i yoki boshqa qadam xato bersa, keyingi qadamga o'tmang; quyidagi rollback bilan eski servislarni ishga tushiring. SQLite server uchun yuqoridagi PostgreSQL dump buyrug'ini ishlatmang: alohida SQLite backup zarur.

`sync_public_snapshot --apply`, seed, `loaddata`, `flush` va `docker compose down -v` ushbu yangilash qadamlariga kirmaydi. Ular serverda admin kiritgan kontentni almashtirishi yoki ma'lumotlarni yo'qotishi mumkin. Git push lokal bazani serverga ko'chirmaydi.

## 5. Natijani tekshirish

```bash
docker compose ps
docker compose logs --tail=80 backend frontend
curl -f http://127.0.0.1:8005/api/v1/interviews/
curl -f -o /dev/null http://127.0.0.1:3005/interviews
curl -f -o /dev/null http://127.0.0.1:3005/impact/recognized
```

Servis endi ko'tarilayotgan bo'lsa, curl tekshiruvlarini qayta bajaring. Domen orqali admin va saytni ochib, bir marta Ctrl+F5 bosing. Intervyuni tahrirlang, saqlang va nashr qilingan yozuvning matni ommaviy sahifada mosligini tekshiring. Qoralamalar admin panelda qoladi, ommaviy ro'yxatda chiqmaydi. 390px va desktopda filtrlar, menyu va modalning Saqlash tugmasiga skrollni tekshiring.

## Rollback

Yuqorida chiqarilgan aniq zaxira papkasidan foydalaning:

```bash
cd /var/www/alumni
# Agar boshqa SSH terminali ochilgan bo'lsa, haqiqiy papkani kiriting:
# backup="$HOME/alumni-backups/YYYYMMDD-HHMMSS"
docker compose -f docker-compose.yml -f "$backup/rollback-images.yml" up -d --no-build backend frontend
docker compose logs --tail=80 backend frontend
```

Bu oldingi image'larni ishga tushiradi; Git ishchi nusxasi yangi commitda qoladi. Database restore bajarilmaydi va serverdagi keyingi yozuvlar o'chirilmaydi. Eski image'lar bilan ishga qaytgandan keyin yangilanish xatosini alohida tekshiring. Ushbu versiyada schema o'zgarmagani uchun odatiy rollback uchun database restore talab qilinmaydi.
